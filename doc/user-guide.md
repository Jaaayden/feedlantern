# 使用指南

## 用户与登录

“用户管理”列出每个账号的订阅数（含出错和暂停数量）、凭据数、最近活跃时间和创建时间，顶部汇总账号、停用、订阅和出错订阅数；编辑、停用 / 启用和删除位于每行的“⋯”菜单。管理员在侧栏“用户管理”点击右上角“创建用户”，在弹窗中设置用户名及至少 8 字符的初始密码，再将账号信息私下交给对方。所有账号使用同一登录页，不开放自行注册。创建后可编辑用户名、重置密码或切换角色；所有管理员同权，可以管理其他管理员。禁止停用或删除自己，自行降级时必须仍有另一名启用的管理员。改名、改密及角色变化会撤销目标账号的全部登录会话，改名不改变 RSS 地址。

每个账号只看到自己的订阅、Cookie 凭据、批量任务及编辑会话；管理员的日常工作台也遵守这一规则。普通用户可以创建和管理自己的网页订阅与 RSS 翻译，使用管理员统一配置的抓取、翻译服务。普通用户的列表／卡片偏好按账号保存在当前浏览器。

所有用户可在“设置”修改自己的密码，修改后仅此账号的全部登录会话和访问令牌失效。普通用户忘记密码时联系管理员，在“用户管理”重置密码；管理员忘记密码可在服务主机运行 `pnpm admin:reset`。

“停用”会立即撤销该用户登录，关闭其网页编辑会话，取消可取消的抓取和翻译操作，阻止新后台任务及 RSS 访问。旧任务返回的结果不再保存；既有数据保留。重新启用后需要重新登录，原 RSS 地址恢复可用，原本启用的订阅和待处理任务继续执行，手动暂停的订阅保持暂停。

每个用户都可在“设置 → 通知”管理自己的通知渠道（Bark、Webhook、ntfy、Telegram，可同时启用多个）、失败阈值与重试参数，并分别发送测试通知。故障只通知订阅所有者，未启用任何渠道时不发送，也不会回退至管理员的渠道。系统配置和整站备份恢复仅管理员可用。整站备份包含全部用户的数据，管理员应妥善保管。

管理员可以通过侧栏顶部的工作台切换器（显示“我的工作台”或“正在管理”）直接切换到任意账号，也可以在用户列表点击“管理工作台”，进入该账号的订阅、Cookie、批量任务和个人通知。管理他人时侧栏和顶栏改用琥珀色提示，页面顶部持续显示“正在管理：用户名”，点击“返回我的工作台”或在切换器中选择“我的工作台”退出。地址栏会带上目标账号（`#/u/用户ID/…`），刷新或前进 / 后退都会停留在同一工作台。操作使用真实管理员身份，不模拟目标账号登录。停用用户可查看和修改静态配置，新建、抓取、翻译、浏览器操作及通知测试须先启用。Cookie 值不回显，可使用已有凭据或替换，订阅只能绑定同一所有者的凭据。

“删除用户”先展示订阅、凭据和任务数量，再要求输入目标用户名确认。确认后账号、订阅、历史、凭据、任务、个人设置与通知记录永久删除，旧 RSS 地址失效，无法撤销。

## 访问令牌

想用脚本或 AI Agent 管理订阅时，在“设置 → 访问令牌”创建个人访问令牌：填写名称（方便以后辨认），选择权限和有效期。

- **只读（read）**：只能查看订阅、条目、日志等，不能做任何修改。
- **读写（write）**：还可以创建、修改、刷新、删除订阅和凭据等。
- 有效期可选 30 天、90 天、1 年或永不过期。

完整令牌以 `fl_` 开头，**只在创建后显示一次**，请立即复制保存；之后列表只显示开头几个字符、权限、有效期和最近使用时间。不再使用或怀疑泄露时点击“吊销”，使用它的脚本会立即失去访问权限。

令牌代表你本人：只能访问你自己的工作台，权限与你在网页上的权限相同；但不能导出或恢复备份、管理账号，也不能创建或吊销令牌，这些操作只能在网页上完成。修改密码、账号被停用或删除时，全部令牌立即失效。调用示例见[开发与接口](development.md#用令牌调用-api)。

## 创建订阅

登录后点击“新建订阅”，输入网址及可选 Cookie，点击“打开并自动识别”。按钮右侧的箭头还提供“RSS 翻译”和“批量添加”两种方式。软件寻找重复列表并匹配标题、链接及可选字段。明确结果直接预览，有多个合理列表时选择候选；缺少可选字段不阻止保存。

在“调整匹配”中可点选网页内容、切换条目容器、清除错误字段或编辑 CSS 选择器。修改后重新预览，匹配有效才可保存。手动字段会在重新识别时保留，除非明确选择替换。

网页加载后会逐屏滚动，触发滚动入场动画和视口内的延迟加载，再恢复原位置。编辑预览、批量识别和后台刷新使用相同流程；滚动最多 20 步或 8 秒，到底部稳定后提前结束。只处理当前页，不点击“查看更多”或翻页，不能保证完整采集无限滚动或虚拟列表。

### 日期点选

日期和来源、分类混在一行时，选择“日期”后点击时间所在区域即可。框选仍表示整个容器，提示和预览显示提取出的时间；无需为“3 分钟前”寻找独立标签。也可以在高级匹配规则中填写日期容器的 CSS 选择器。

优先采用有效的 `datetime`；其次解析直属文本，再检查完整文本。支持“刚刚”“3分前”等秒、分钟、小时、天、周前及英文对应表达。相对时间按本次页面加载时刻估算，预览显示“估算”，保存后同一链接的估算时间不随刷新漂移；之后取得准确时间可纠正估算。多个无法区分的日期、“昨天”、月／年前等含糊表达不猜测，解析失败不会抹去历史日期。

霂明导航的 `/intel` 页面按文章链接读取内嵌数据中的准确时间戳；未匹配时使用页面提供的时间基准估算。清空日期规则会停止提取新日期，已经保存的历史日期保留。

## 订阅设置

点击列表或卡片中的“订阅设置”，或点击订阅名称后切换到“订阅设置”标签。订阅地址、刷新状态和“立即刷新”固定在面板上方，下方依次是“订阅内容”“抓取日志”“订阅设置”三个标签；设置有未保存的修改时，关闭面板或切换标签会先提示。名称和刷新间隔直接显示，点击“保存设置”即可生效，无需打开或预览目标网页。修改名称同时更新订阅列表名称和 RSS 频道标题；仅改名称时，地址、历史和调度不变。编辑匹配中的名称也使用同一设置。升级时若旧版本两个名称不同，会保留阅读器名称并同步到列表。阅读器已保存的名称或用户自定义名称可能不会自动更新。

刷新间隔支持 5–1440 分钟的整数。间隔变化后从保存生效时重新计时，不会立即抓取；已暂停订阅继续暂停，恢复时会立即刷新。关闭设置或进入“编辑匹配规则”前，如果有未保存修改，会提醒确认丢弃。暂停或轮换密钥不会清空正在填写的设置。

### 输出内容：条目过滤与输出条数

“订阅设置 → 输出内容”控制订阅地址里发布哪些条目，RSS、Atom 和 JSON Feed 三种地址共用同一设置。过滤只影响输出，已存储的条目不会被删除，修改后立即生效，改回或清空规则即可恢复。

- **包含关键词**：每行一个。填写后，只输出标题或摘要包含其中任意一个的条目。
- **排除关键词**：每行一个。标题或摘要包含任意一个就不输出，优先于包含关键词。
- 匹配不区分大小写，看的是输出中的标题和摘要（RSS 来源和翻译订阅按去掉 HTML 标签后的正文）。翻译订阅匹配翻译后的内容，双语模式同时包含原文；翻译未完成的条目本来就不输出。
- **按正则表达式匹配**：勾选后每条按正则处理，对标题和摘要分别匹配，所以 `^\[广告\]` 表示标题以“[广告]”开头。为避免拖慢输出，每条不超过 200 个字符、每类最多 30 条，不支持嵌套重复（如 `(a+)+`、`(a|b)+`）和反向引用；单个订阅的正则运行超过 100 毫秒会被中断，本次输出暂不过滤，并在设置页提示。保存时会先在已有条目上试运行。

填写时，下方实时显示“已存储 N 条，输出 X 条，过滤 Y 条”；保存后，“订阅内容”中被过滤的条目淡化显示，并标注“命中排除关键词”或“未命中包含关键词”，超出输出条数的条目标注“超出输出条数”。

**输出条数**支持 10–500，默认 100，过滤之后再计算条数。网页订阅保留 max(200, 输出条数) 条历史，RSS 翻译订阅保留 max(100, 输出条数) 条；调小输出条数不会立即删除数据，下次抓取时再按保留量清理；调大后由之后抓到的新条目逐步补足。

## 日常管理

默认使用列表，可切换卡片并记住偏好。两种视图支持直接复制 RSS、打开订阅设置与选择。点击名称查看内容、来源和刷新状态；从订阅设置进入“编辑匹配规则”，编辑完成或返回后回到设置。列表上方的状态栏显示订阅总数、自动更新数、已收集条目和需要检查的订阅数。全选复选框位于列表表头，搜索后只作用于当前结果，“状态 → 需要检查”仅显示有抓取错误的订阅，可与搜索、来源和输出筛选组合使用，方便逐项查看。改变搜索、来源、输出或状态筛选会清空选择。

多选后，列表上方会出现批量操作栏，点击“批量修改设置”，可统一设置翻译输出模式（双语、仅中文、原文）、刷新间隔（5–1440 分钟）和输出条数（10–500）。模式默认“保持原值”，间隔和条数留空则不修改，可以只改一项；条目过滤只能逐个订阅设置（接口支持批量传入 `itemFilter`）；网页和 RSS 订阅均支持。保存沿用单个订阅的设置逻辑，不重新抓取来源，暂停状态保持不变。

批量复制每行一个 RSS 地址；“导出 OPML”（列表表头导出当前结果，批量操作栏导出所选订阅）生成标准 OPML 文件，可一次导入 NetNewsWire、Reeder、Inoreader、Feedly 等阅读器。支持暂停、恢复、刷新和删除。失败逐项显示，成功项目不回滚，失败项保留选择。选择较多订阅时，界面自动分批请求；立即刷新使用少量并行的单订阅请求，避免整批共用一个长请求；实际抓取并发由服务端配置控制，同一来源 hostname 仍串行。删除会同时删除该订阅历史；密钥轮换会立即撤销旧 RSS、Atom 和 JSON Feed 地址。

## 订阅地址、格式与浏览器预览

同一订阅提供三种格式，内容、过滤规则和输出条数完全相同，按阅读器支持的格式选择：

| 格式 | 地址 | Content-Type |
| --- | --- | --- |
| RSS 2.0 | `/feeds/订阅ID/密钥.xml` | `application/rss+xml` |
| Atom 1.0 | `/feeds/订阅ID/密钥.atom` | `application/atom+xml` |
| JSON Feed 1.1 | `/feeds/订阅ID/密钥.json` | `application/feed+json` |

订阅面板的“订阅地址”上方可在 RSS 2.0、Atom 1.0、JSON Feed 1.1 之间切换，复制按钮随之变为“复制 Atom 地址”等，选择按浏览器保存。列表中的“复制 RSS”、批量复制和 OPML 导出仍使用 RSS 地址。三种地址使用同一个密钥，轮换后同时失效。

RSS 地址形如 `/feeds/订阅ID/密钥.xml`。阅读器、命令行工具和脚本读取它时始终得到标准 RSS 2.0（包含 `ttl` 刷新间隔、`generator`，有图片的条目附带 `media:thumbnail` 缩略图）。直接在浏览器地址栏打开同一地址时，会显示一个可读页面：订阅名称、来源、复制按钮和最近 30 条内容，页面底部提供“查看原始 XML”（地址后加 `?format=xml`）。

Atom 和 JSON Feed 地址没有预览页；在浏览器中直接打开时分别以 `application/xml`、`application/json` 返回原文，方便查看而不是下载。

只有浏览器顶层打开 RSS 地址时才会显示预览：判断依据是浏览器自动附带的 `Sec-Fetch-Dest: document`、`Sec-Fetch-Mode: navigate` 和 `Accept: text/html`。阅读器、浏览器插件的后台请求和页面脚本都不会发送这组请求头，因此不会被误判成网页。预览页同样需要密钥，和 RSS 内容一样请勿公开分享；响应带 `X-Robots-Tag: noindex`，避免被搜索引擎收录。

## 界面与主题

顶栏右上角的按钮在“跟随系统”“亮色”“暗色”之间切换，选择按浏览器保存。地址栏会记住当前页面和打开的订阅面板（例如 `#/settings`、`#/feed/订阅ID/logs`），刷新后保持原位，浏览器的前进 / 后退也可使用。在订阅页按 `/` 可直接搜索，按 Esc 清空搜索。列表可按添加顺序、名称、最近更新或“需要检查优先”排序；点击状态栏的“需要检查”或订阅下方的错误原因，可分别筛选出错订阅或直接打开该订阅的抓取日志。手机上主导航移到屏幕底部，订阅面板从底部弹出。设置页左侧（手机上为顶部横向标签）可快速跳到应用设置、通知、Cookie 凭据、账号与密码、备份与迁移和关于。

## 批量添加

点击“新建订阅”右侧的箭头，选择“批量添加”。每行一个网址，最多 100 个；先修正无效行，重复行会跳过。可统一刷新间隔并逐行选择 Cookie。

明确结果自动创建；歧义结果显示候选样例，点击“打开并调整匹配”后重新加载验证并保存。失败可重试，已存在网址复用原订阅。任务在后台执行，关闭页面不会停止，重启后恢复。取消只影响未开始的项。结果页可以复制整批订阅地址。

## Cookie

在“设置 → Cookie 凭据”中粘贴 Cookie 字符串或 OpenCookie 兼容 JSON，可以上传 JSON 文件。凭据可以命名、替换并供多个订阅引用；只有域名兼容时才会携带。过期或失效需从已登录浏览器重新导入。服务不提供交互登录或验证码处理。

## 兼容范围

支持普通 DOM 列表、动态渲染和 Cookie 页面。暂不支持全文、自动翻页、无限滚动采集、iframe 内部点选、封闭 Shadow DOM 和 Canvas 内容。规则失效时保留历史，修复前不会静默替换规则。

“调整匹配”会把网页截成长图，在本地用滚轮或触控板滚动，不再等待服务器。截图按每段 8000 像素分段：滚动到接近底部时自动加载下一段；自动识别的列表在下面时，会先加载到那里再滚动过去。最多显示 48000 像素，更长的网页会在底部注明。鼠标悬停时会立即框出将要选中的元素并显示其标签；按 ↑ / ↓ 扩大或缩小范围，点击即选中，并在同一次请求中刷新订阅预览。选中后也可以用“扩大 / 缩小”按钮调整。

需要先进入另一个列表页时，按住 ⌘（Windows / Linux 为 Ctrl）点击网页中的链接。画面跳转后，选择“以此页为源网址”会把该页填入源网址并重新识别；“返回源网址”回到原页面。跳转期间不能点选或保存，避免规则与源网址不一致。只有当网页里有独立的内部滚动区域时，才会出现上下按钮，用于滚动远端网页的内部区域。退出编辑或离开页面会释放远端编辑会话。

日期自动识别优先选取包含直属时间文本的元信息区域，避免选中整个条目父容器。手动点选时仅高亮可解析的时间文本；保存的仍是容器选择器，支持“分类 · 来源 · 27 分钟前”这类混合内容。

## 抓取日志

点击订阅名称打开订阅面板，切换到“抓取日志”标签。每条记录展示执行时间、来源、状态、耗时、有效条目数、新增条目数及失败原因。可按状态筛选，每页 20 条，通过“加载更多”查看历史；最新页每 5 秒自动更新，查看历史或离开标签后暂停更新。

日志默认保留最近 30 天，可在设置页调整，定时、手动（包括批量刷新）、创建、修改规则、恢复订阅和批量创建均会记录实际发生的抓取。并发请求合并成一次抓取时只记录一次，来源取最先发起该任务的入口。没有新文章仍算成功，无法提取有效条目算失败；失败保留已有文章。服务异常重启留下的执行记录显示“中断”，耗时未知。

在“设置 → 通知”启用至少一个渠道（Bark、Webhook、ntfy 或 Telegram）后，连续失败达到个人阈值时会发到所有已启用的渠道，详情逐个渠道显示“待发送／待重试／已发送／发送失败／已取消”，例如“通知：Bark 已发送 · Webhook 发送失败（…）”；没有启用任何渠道显示“通知：未启用”。同一连续故障只告警一次，多条失败日志关联同一告警状态。恢复成功后重置，下次失败可再次告警，默认不推送恢复消息。配置步骤见[配置参考](configuration.md#故障告警与通知渠道)。

## RSS 中文与双语订阅

点击「新建订阅 → RSS 翻译」，输入现有 RSS 2.0 或 Atom 1.0 地址，点击「预览订阅源」。确认原文后填写名称、刷新间隔和输出模式，保存即可复制新的 RSS 地址。

- 默认每 30 分钟刷新，输出简体中文双语内容。标题中文在前，正文在同一内容块中先显示译文，再显示原文；代码不翻译。
- 首次导入只处理源中最新 20 条，后续处理新条目和已导入条目的变化，默认输出最近收集的 100 条（可在“输出内容”中调整，见上文）。首次跳过的旧条目不会在下一次刷新时自动补翻。
- 只翻译订阅源提供的内容：有全文就翻译全文，只有摘要就翻译摘要，不另行访问文章页面。第一版 RSS 输入不附加 Cookie；可使用源自身提供的带访问令牌的订阅地址。
- 图片、链接、列表、表格和代码保留；不安全的 HTML 会被清理。管理页面正文在隔离预览框中展示，预览中的链接不会跳转管理页面；可用条目标题打开原文。
- 翻译在后台进行。阅读器获取订阅时只读取缓存，不等待 Google。只有标题和正文均翻译成功的文章才会输出到订阅链接；等待、失败和部分完成的条目不会输出。首次尚无成品时返回有效的空 RSS。管理页仍显示原文和处理状态。
- 订阅详情显示翻译完成、等待和失败数量；失败原因显示在条目旁。可点击「重试未完成翻译」。暂停订阅也会暂停新翻译，恢复后继续。
- 在订阅设置中切换「仅中文／双语」，输出地址与条目 ID 保持不变，无需重新翻译。修改 RSS 来源地址会清除该订阅原有条目，从新来源重新开始；保存前应确认地址。

### Google 免费翻译（实验性）

使用 Google 浏览器翻译通道（`translate-pa.googleapis.com/v1/translateHtml`），与沉浸式翻译 1.33.1 发布脚本的浏览器模式采用相同请求格式，无需申请云账户或配置付费 API。它不是 Google Cloud Translation 官方付费接口，没有可用性保证，可能因服务器出口 IP、请求频率或接口变化而失败。首次使用时请在实际部署服务器验证连通性。

默认最多同时发出 6 个翻译请求，启动间隔为 100 毫秒；同一篇文章的标题、正文片段和长文本分段可并行处理，最终按原文顺序组装。可在「设置 → RSS 翻译速度」调整并发数（1–16）和启动间隔（0–5000 毫秒），0 表示不额外间隔，保存后生效。成功片段持久缓存；同样的片段可跨条目复用。临时失败最多尝试 3 次，分别至少等待 60 秒和 300 秒，并遵循服务端 `Retry-After`（最多 24 小时）。只有明确的限流响应（例如 429、403、自动化请求限制页面或 Retry-After）会暂缓整条翻译队列；普通单条错误不阻塞其他订阅。手动重试不会跳过仍有效的限流等待期。超出尝试次数后需要手动重试。

Google 请求被限制时，网页抓取、RSS 输出和已有译文继续可用，不会自动切换到收费服务。文章原文有变化时，旧译文不会冒充最新内容；未完成的新版本暂不进入 RSS 输出，管理页可查看原文，已成功片段仍可复用。

RSS 获取失败会进入既有抓取日志和失败告警流程（取决于你的通知设置）；翻译失败显示为独立翻译状态，向所有者所有已启用的通知渠道发送独立告警。完整加密备份包含译文、缓存和未完成任务；轻量配置导出不含内容，导入后重新获取。片段缓存最多保留最近使用的 20,000 段，定期清理；保留条目的成品译文不因此丢失。

### RSS 翻译进度与日志

订阅详情中的翻译进度每 2 秒更新，可查看每篇文章的状态、片段完成数量、缓存命中、失败原因和下次重试时间。翻译日志每个订阅保留最新 200 条（且不超过 7 天），界面显示最近 100 条；服务端标准输出也记录翻译事件。全站请求数包含其他 RSS 翻译订阅。

翻译请求使用原生文本数组，合并最多 50 个片段（合计原文不超过 1800 字符），再按设置并发提交。返回数量不符、类型异常或包含空译文时，整批拒绝写入缓存和发布。已有完整译文保留；新通道使用独立片段缓存，避免混用旧接口结果。Google 免费接口实际返回限流时暂停请求并自动重试；管理页显示恢复调度时间。仅整篇翻译完成后才进入公开订阅。

每个通知渠道都提供“发送测试通知”，使用当前填写的值发送一次测试，不保存设置，也不要求启用自动告警。启用任一渠道后，首次翻译失败（含限流）会推送到所有已启用的渠道；同一订阅连续失败去重，与抓取故障分别处理。全部文章翻译恢复成功后重新允许告警。推送失败沿用“告警策略”中的发送次数、重试间隔和冷却设置，每个渠道分别重试。翻译本身最多尝试 3 次：第一次失败后至少 1 分钟，第二次后至少 5 分钟；Google 限流还触发至少 1 分钟的全局退避，并遵守更长的 Retry-After。第三次失败后可在订阅详情手动重试。

### 批量添加 RSS 翻译

在“新建订阅”的下拉菜单中选择“批量添加”，将“批量订阅类型”切换为“RSS 翻译”，每行填写一个 RSS/Atom 地址，选择统一的中文或双语输出及刷新间隔，然后点击“开始批量添加翻译”。每批最多 100 个地址，可点击“从 OPML 导入”读取阅读器导出的 OPML 文件；重复项自动跳过；同址网页订阅与翻译订阅分别识别。后台读取订阅源后自动创建订阅并启动翻译，源读取失败可在批量任务中重试。任务显示“已创建”表示订阅创建完成，文章翻译进度请到订阅详情查看。关闭页面后任务继续运行。

### 网页抓取订阅翻译与列表筛选

订阅列表和卡片分别显示来源（网页抓取 / RSS 来源）与输出模式（原文 / 中文翻译 / 双语翻译），可按来源或是否翻译筛选，全选仅作用于当前筛选结果。

网页订阅在“订阅设置 → 输出模式”选择中文或双语即可开启翻译。系统处理已有标题和抓取摘要，保留图片与条目标识，后续抓取内容变化时重新翻译；不额外访问文章全文。只有完成翻译的条目进入公开 RSS，可在详情查看进度、日志及重试，失败沿用 Bark 告警。切回原文立即恢复原始输出，订阅地址不变。升级时已有网页订阅默认保持原文输出。
