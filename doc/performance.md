# 双路径性能验证

> 后续调整：已按实际使用反馈撤回滚轮交互，远端网页恢复上下按钮滚动。下文保留当时性能实验记录；后台刷新、并发和截图体积优化继续保留。

2026-09-09；基线为 `f3dd999`，候选为本次本地优化。环境：macOS arm64、Node.js 26.7.0、Playwright 1.63.0。固定场景各重复 3 次，各配置依次执行，不同时运行其他测试。以下毫秒数据为“中位数 / 最大值”，样本量不足以估计生产 P95。

## 方法与边界

- 五种场景：静态、200 ms 后动态插入、10,000 px 横幅长页面、滚动后延迟插入、Cookie 保护页面。每页 12 条，额外等待统一为 300 ms（产品默认仍为 1000 ms）。
- 并发基准直接调用真实 BrowserService 和共享任务池；四个逻辑站点复用一个 loopback 测试服务器，避免修改本机 DNS。真实 hostname 的互斥另由 API 与任务池测试验证；此基准不是公网网站测试，也不是完整生产 HTTP 服务压测。
- 比对各次抓取的全部字段；仅归一化测试服务器随机端口。四种配置的 15 次结果均与基线一致，每次 12 条。图片字段、登录隔离和日期语义另由完整回归验证。
- 资源为基准 Node 进程及其 Chromium 子进程的 RSS 合计，每 200 ms 采样；RSS 合计可能重复计算共享页，不等于容器实际内存。后台资源在创建模拟前端前记录。CPU 为 ps 提供的进程生命周期平均 %CPU 的采样峰值，可超过 100%，不是瞬时 CPU 峰值。
- 编辑画面显示测试通过本机 HTTP 传输真实截图 JSON，用另一页面执行图片 decode 和两次 requestAnimationFrame；不含公网 RTT、React 渲染及反向代理影响。交互正确性由真实编辑器端到端测试覆盖。

## 单个订阅抓取

不含排队，包含上下文创建、加载、等待、预滚动、提取与清理；数据库写入单独测量。

| 场景 | 基线 ms | 优化后、并发 1 ms |
|---|---:|---:|
| 静态 | 1598 / 1735 | 1599 / 1692 |
| 动态 | 1597 / 1597 | 1565 / 1565 |
| 长页面 | 6089 / 6129 | 3689 / 3720 |
| 懒加载 | 1864 / 1896 | 1594 / 1596 |
| Cookie | 1596 / 1603 | 1597 / 1604 |

长页面收益主要来自中间滚动等待 300 → 150 ms；底部和恢复位置仍保留 300 ms，次数和时间上限不变。短页面耗时变化较小。已有滚动揭示、延迟揭示、持续增长测试通过；没有真实订阅样本，不能保证任意站点都获得同样收益。

## 并发、排队与资源

| 配置 | 五页整批 ms | 单次抓取 ms（混合场景） | 排队 ms | 后台 RSS 峰值 MiB | CPU 采样值 % |
|---|---:|---:|---:|---:|---:|
| 基线 1 | 12756 / 12900 | 1603 / 6129 | 3199 / 11333 | 554 | 101.1 |
| 优化 1 | 10038 / 10186 | 1597 / 3720 | 3166 / 8579 | 533 | 105.1 |
| 优化 2 | 5345 / 5498 | 1605 / 3745 | 1597 / 3368 | 637 | 101.3 |
| 优化 4 | 3743 / 3885 | 1656 / 3883 | 0 / 1772 | 842 | 123.3 |

默认仍为 1。多个独立站点且内存有余量时建议先试 `BACKGROUND_CONCURRENCY=2`；4 的内存峰值明显更高，不作为弱机器默认值。来源集中在同一 hostname 时仍串行，不能按此表预期提速。

## 验证与复现

- 完整单元测试 59 项通过，完整端到端测试 18 项通过；后续鼠标位置缓存改动的 4 项浏览器测试与 5 项编辑器端到端专项回归也全部通过。类型检查与生产构建通过。
- 覆盖跨站并发、同站互斥、同订阅重复请求合并、修改网址后的锁重新计算、队列屏障、失败释放容量、批量识别共享容量、Cookie 隔离与失败保留历史。
- 无键的编辑、删除等操作作为屏障；维护与关闭先停止接收任务并 drain，再恢复数据库或关闭浏览器。

```sh
PLAYWRIGHT_BROWSERS_PATH=0 pnpm test
PLAYWRIGHT_BROWSERS_PATH=0 pnpm test:e2e
pnpm build
PLAYWRIGHT_BROWSERS_PATH=0 pnpm exec tsx scripts/performance.ts > /tmp/performance-1.json
PLAYWRIGHT_BROWSERS_PATH=0 PERF_CONCURRENCY=2 pnpm exec tsx scripts/performance.ts > /tmp/performance-2.json
PLAYWRIGHT_BROWSERS_PATH=0 PERF_CONCURRENCY=4 pnpm exec tsx scripts/performance.ts > /tmp/performance-4.json
```

比较旧版本时，把基线源码放入独立临时目录，复用相同 node_modules，并设置 `PERF_SOURCE=/absolute/path/to/baseline`，并发保持 1。基准只操作临时数据库与本机测试页面。所有配置应顺序运行。

每次测量的分段数据与内容摘要保存在 [原始记录](history/performance-2026-09-09.json)。
